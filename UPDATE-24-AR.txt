LARA STOCK — التحديث 24: مراقبة الأخطاء وسلة مشتريات الموقع

1) مراقبة الأخطاء
- من لوحة أدمن البوت: «🩺 مراقبة الأخطاء».
- من كونسول الموقع: قسم النظام ← «مراقبة الأخطاء».
- سجل للأخطاء التقنية والتحذيرات في البوت والموقع وAPI والمهام الخلفية.
- لكل خطأ: السبب، نوع الاستثناء، المستخدم واسم حسابه عند توفره، المصدر، العملية، المنتج، وقت أول وآخر ظهور، عدد التكرارات، مكان الخطأ ومسار الدوال.
- أخطاء الواجهة في المتصفح ترسل تقريراً موثقاً بحساب المستخدم مع تحديد معدل الإرسال.
- تنبيه للأدمن للأخطاء المهمة مع زر يفتح التفاصيل مباشرة.
- التكرار لنفس الخطأ له مهلة تنبيه 10 دقائق، وحد عام 15 تنبيهاً في الدقيقة.
- زر لتفعيل التنبيهات أو إيقافها؛ إيقاف التنبيهات لا يوقف تسجيل الأخطاء.
- عرض جميع الأخطاء أو غير المعالجة، صفحات وتحديث، وربط بصفحة المستخدم.
- يمكنك وضع علامة «تمت المعالجة». تكرار الخطأ بعد ذلك يعيد فتحه.
- البيانات الحساسة، مثل التوكنات والمفاتيح والكوكيز وكلمات المرور، تُحجب قبل حفظ التقرير.
- سجل بمدة احتفاظ 30 يوماً؛ التسجيل يعمل بطابور محدود وذاكرة احتياطية عند تعطل MongoDB، مع إعادة محاولة الحفظ.
- الأخطاء غير المرتبطة بمستخدم تظهر كمهام خلفية؛ لا تُنسب لشخص بالتخمين.
- التقاط الأخطاء من سجلات التحذير والخطأ، الاستثناءات غير المعالجة، معالجات البوت، طلبات الموقع وAPI، وتقارير المتصفح.
  الأخطاء التي تخفيها أجزاء قديمة بصمت دون تسجيل أو استثناء ظاهر ليست مضمونة الظهور في السجل.

2) سلة الموقع
- السلة للعملاء داخل الموقع فقط، مع بقاء الشراء المباشر في البوت والموقع.
- زر السلة بجانب ترحيب المتجر، مع عداد وملخص عائم عند وجود منتجات.
- تصميم فاتح وداكن بألوان الأزرق والأبيض، مناسب للهاتف والكمبيوتر وRTL.
- ثلاث مراحل: السلة ← مراجعة الطلب ← النتيجة.
- إضافة حتى 20 منتجاً مختلفاً، تعديل الكمية أو الإزالة، وعرض خصومات الكمية وVIP.
- تعديل بريد الدعوة والمدة للمنتجات التي تحتاجها من داخل السلة.
- حفظ محتوى السلة محلياً لكل حساب بشكل مستقل. الأكواد المشتراة لا تحفظ في التخزين المحلي للمتصفح.
- مراجعة الأسعار والمخزون والرصيد من الخادم؛ أسعار العميل أو الإجمالي المرسل منه لا تعتمد للخصم.
- السعر المعروض للمراجعة صالح حتى 15 دقيقة مع إعادة فحصه قبل التنفيذ؛ المخزون لا يُحجز أثناء التصفح.
- أي تغير في السعر أو التخفيضات أو التوفر يتطلب مراجعة جديدة قبل الخصم.
- خصم الرصيد والتسليم يستخدمان مسارات البوت الحالية: المنتجات العادية واليدوية والدعوات والموردون.
- تُنفذ المنتجات بالتتابع. إذا تعثر منتج أو احتاج تحقق المورد تتوقف المنتجات التالية، ويظهر ما نُفذ وما دُفع وما بقي.
- لكل محاولة مرجع محفوظ في MongoDB، ولكل منتج مرجع يربطه بالطلب الحقيقي.
- تكرار تأكيد نفس المحاولة لا ينفذ شراءً ثانياً.
- بعد انقطاع الرد تسترجع النتيجة من الخادم، بما فيها الأكواد، دون إعادة الشراء.
- في حال انقطاع حفظ الإيصال بعد نجاح الطلب، يمكن استرجاعه من سجلات الطلبات المرتبطة.
- لا يعاد تنفيذ شراء بقيت نتيجته مجهولة تلقائياً؛ تظهر مراجعة للدعم بدلاً من خصم جديد.
- بعد إعادة فتح الصفحة يوجد زر لعرض آخر محاولة شراء.
- لإيقاف السلة: لوحة الأدمن ← «🛒 سلة الموقع»؛ أو من كونسول الموقع ← «إعدادات سلة الموقع».

3) اللغة والإعدادات
- نصوص السلة بالعربية والإنجليزية والروسية والصينية حسب لغة الموقع.
- الإيموجيات والصور الموجودة للمنتجات تستخدم داخل السلة أيضاً.
- الإعدادان الجديدان يحفظان في MongoDB من لوحة الأدمن؛ لا حاجة لإضافة متغيرات جديدة إلى .env.
- لم تُحذف أي دالة أو كلاس سابق. الحزمة تشمل التحديثات السابقة وإعداداتها.

4) التحقق
- 356 اختبار Python ناجحاً، بينها 35 اختباراً للسلة و16 لمراقبة الأخطاء.
- python -m py_compile bot.py: ناجح. فحص الأسماء غير المعرفة: صفر.
- Node JavaScript syntax: ناجح.
- تجربة Chromium حقيقية على خادم محلي: كمبيوتر وهاتف، فاتح وداكن وRTL، كميات وخصومات، انقطاع الرد بعد الشراء، استرجاع الإيصال بعد إعادة الفتح، إلغاء مراجعة لم تبدأ، وتعديل إيميل الدعوة.
- فحص عدم وجود استثناءات JavaScript في تجربة المتصفح: ناجح.
- كل الفحوص تستخدم حسابات وهمية وقاعدة بيانات في الذاكرة؛ خدمات Telegram والدفع والموردين محاكاة.
- خادم فحص المتصفح يمنع الاتصالات الخارجية حتى على مستوى اتصال socket؛ لا توجد مدفوعات حقيقية في الفحص.
- لم يتم تشغيل الحزمة على جهاز Windows الخاص بك أو إجراء تجربة على هاتف فعلي ضمن هذا التحديث.

بعد التحديث: أعد تشغيل البوت، وأغلق الموقع وافتحه من جديد لتحميل الواجهة الجديدة.

للمطور فقط — إعادة الفحص المعزول:
python -m pip install -r verification/requirements-test.txt
python -m pytest verification -q
واجهة الموقع القديمة يمكن فحصها عبر test_ui.cjs بعد تثبيت jsdom داخل verification/ui-deps.
اختبار المتصفح الجديد: ثبّت playwright محلياً ومتصفحه، ثم شغّل node verification/test_cart_browser.cjs.
الخادم المستخدم داخل الاختبار محلي ومعزول ومهيأ في verification/serve_cart_test.py، ولا يشغل البوت بحسابك الحقيقي.
