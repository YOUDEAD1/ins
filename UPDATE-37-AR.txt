LARA STOCK — التحديث 37: ظهور المنتجات والمجلدات، لغة إشعارات العميل، واستقرار Bybit

هذه نسخة المشروع كاملة، مبنية على الحزمة السابقة مع جميع ملفاتها. لم تُحذف أي دالة أو كلاس أو ميزة من البوت.
التعليمات التالية هي الأحدث؛ تقارير التحديثات السابقة المرفقة محفوظة كسجل تاريخي.

ما تغير
1) الحركات على الهاتف
- تخفيف المؤثرات المعقدة وحد الحركات الثلاث يطبقان على الوضع المحدود فقط: الهاتف الذي يعلن ذاكرة 4 جيجابايت أو أقل، أو أربعة أنوية أو أقل، وكذلك وضع توفير البيانات. الأجهزة الأخرى تحتفظ بأقنعة SVG وحركة رسم الشعار والحروف والمؤثرات الأصلية.
- تظل تحسينات الرسم التدريجي والبحث وإزالة مشغلات الحركة المنفصلة وتوقفها في الخلفية موجودة. جميع المنتجات متاحة للبحث والروابط المباشرة من البداية.
- عدم إعلان المتصفح بيانات الذاكرة أو الأنوية لا يعني تلقائيًا أنه جهاز ضعيف. إعداد تقليل الحركة في الجهاز يبقى محترمًا.

2) إخفاء المنتج بعد 3 أيام من عدم التوفر
- يبدأ العداد من أول رصد مؤكد لمخزون صفري، ويُحفظ في MongoDB ويستمر بعد إعادة التشغيل. قدم المنتج أو وقت تعديل اسمه لا يحددان مدة النفاد.
- إذا لم يكن للمنتج سجل نفاد موثوق، يبدأ العد بعد تشغيل هذا التحديث؛ لا تُخمن حالة المخزون في الأيام الماضية.
- الفحص كل 5 دقائق. بعد 72 ساعة متواصلة من النفاد يُخفى المنتج تلقائيًا. المنتجات اليدوية غير محدودة المخزون لا تعتبر نافدة.
- عودة المخزون تعيد إظهار المنتج الذي أخفاه النظام وتعيد عداد النفاد من البداية عند نفاده لاحقًا. الإخفاء اليدوي يبقى مقدمًا ولا يُلغى بسبب توفر مخزون.
- إذا أظهرت منتجًا يدويًا أثناء نفاده، يُحترم اختيارك لتلك فترة النفاد؛ تبدأ القاعدة المعتادة من جديد بعد عودة مخزون مؤكدة.
- فشل قراءة قاعدة البيانات أو رد المورد المجهول أو تعذر الاتصال بحساب المقاعد لا يتحول إلى إثبات مخزون صفري.
- الفحص لا يضيف طلبات HTTP إلى الموردين. يقرأ معرّفات المخزون المحلية بتجميع، ويجري انتقالات الحالة دفعة واحدة داخل قاعدة البيانات. أضيف فهرس للمخزون يناسب هذا الفحص.

3) المجلدات والعدادات
- المجلد الفارغ أو الذي لا يحتوي أي منتج ظاهر يُحجب تلقائيًا عن العملاء. وجود منتج ظاهر واحد يكفي لبقاء المجلد ظاهرًا.
- المخفي والمحذوف والمكرر بصيغ معرّفات مختلفة لا يزيد عداد المجلد. روابط ChatGPT المتعددة لنفس المنتج تُدمج في منتج واحد مع حفظ عضوياته.
- عداد المجلد وقائمته داخل البوت وداخل الموقع يعتمدان على نفس المنتجات الظاهرة. يشمل ذلك المنتجات الخارجية.
- من لوحة الأدمن ← إدارة الكتالوجات: يوجد إخفاء/إظهار لكل مجلد، وزران لإخفاء جميع المجلدات وإظهارها. المجلدات الفارغة تبقى متاحة للإدارة.
- الإخفاء اليدوي للمجلد يخفي منتجاته عن العملاء أيضًا، مع حفظ المنتجات وبياناتها. إذا كان المنتج في مجلدين، يبقى متاحًا عبر المجلد الظاهر.
- المجلد الذي أظهرتَه يدويًا يبقى مخفيًا عن العميل ما دام لا يحتوي منتجات ظاهرة. يظهر تلقائيًا عند عودة أول منتج ظاهر إليه.
- السلة والروابط القديمة وتأكيدات الشراء تعيد التحقق من الظهور قبل الخصم. تاريخ المشتريات وبيانات الاشتراكات القائمة لا يُحذف.

4) لغة إشعارات الرصيد والإحالات
- يحفظ الموقع اختيار العربية أو الإنجليزية أو الروسية أو الصينية في الحساب، ويستعيده عند فتح الموقع من جهاز جديد.
- إشعارات مكافأة شراء المدعو، تقدم الإحالات، اعتماد مكافأة الدفعة، الاسترجاع والتعويض، إضافة الرصيد أو خصمه، والإيداع تقرأ لغة التطبيق المحفوظة حديثًا.
- يُستخدم نص CMS المطابق للغة المختارة فقط، ويُستبدل تنسيقه غير الصالح بنص افتراضي من اللغة نفسها. أضيفت النصوص الافتراضية الناقصة بدل النصوص الإنجليزية الثابتة في المسار العربي.
- تغيير العربية/الإنجليزية من البوت يحدث اختيار الإشعارات كذلك. قوائم البوت القديمة العربية/الإنجليزية محفوظة؛ اختيار الروسية/الصينية لا يبدل مفاتيحها الداخلية.
- رسائل قناة اللوق الإدارية تظل بالإنجليزية حسب إعداد المشروع السابق.
- قواعد احتساب المكافآت والأرصدة وأسعار الدفعات القديمة محفوظة. لا توجد إعادة تسعير للإحالات القديمة أو تسوية جماعية لأرصدة المستخدمين ضمن هذا التحديث.

5) Bybit
- جرى فصل فشل HTTP والرد غير JSON أو الناقص عن خطأ Bybit ذي كود صحيح. لن تظهر رسالة retCode=None retMsg=None المبهمة؛ يظهر سبب محدد وحالة HTTP أو كود API حين يتوفر.
- لا يُقبل الرد الناقص كإثبات إيداع ولا يُحسب كمفتاح API غير صالح. لا تُعرض محتويات الرد أو المفاتيح في التشخيص الجديد.
- توجد مهلة قبل المحاولة التالية، مع تهدئة التنبيه المتكرر، وإيقاف التوسع في البروكسيات عند رفض HTTP/API. بديل البروكسي للشبكة محفوظ بمحاولتين كحد أقصى مع توقيع جديد لكل محاولة.
- تغيير بيانات الاتصال يزيل مهلة الخطأ السابق ويسمح بالمحاولة فورًا. حماية تعطيل المفتاح بعد تكرار الخطأ المؤكد 10003 محفوظة.
- هذا يعالج طريقة التعامل مع الأعطال. لا يثبت سبب رد الخدمة السابق دون استجابة HTTP الأصلية، ولا يثبت صحة المفاتيح أو صلاحيات الحساب الحقيقي.

التحقق
- 760 اختبار Python ناجحًا، دون فشل أو تخطي. منها اختبارات التحقق والإحالات القديمة والأرصدة والسلة والشراء وBybit المعزولة.
- 10 مجموعات متصفح ناجحة: التحميل، السلة، الشبكة، الإحالات، فحص المستخدم، استعادة الاتصال، تشخيص الأخطاء، استبعاد أخطاء الإضافات، المجلدات واللغات الجديدة، وأداء الهاتف.
- اختبار 600 منتج على شاشة 360×740 مع إبطاء CPU ست مرات: بدأ العرض بـ12 بطاقة في الوضع المحدود. بقية المنتجات تبقى قابلة للبحث والفتح والتمرير.
- اختُبرت الحركات الأصلية على تعريف Android قوي، وتعريف iOS دون بيانات ذاكرة، والكمبيوتر؛ واختُبر وضع الهاتف المحدود مع غياب IntersectionObserver.
- python -m py_compile bot.py ناجح، ونجح فحص صياغة جميع مقاطع JavaScript السبعة. لا توجد تشخيصات lint جديدة مقارنة بالنسخة السابقة.
- جميع التعريفات السابقة محفوظة: 1348 دالة/كلاس Python إلى 1362، و331 دالة واجهة مسماة إلى 332.
- الاختبارات محلية ببيانات وهمية وقاعدة ذاكرة. لم يُشغل البوت الحقيقي، ولم تُرسل رسائل لمستخدمين حقيقيين أو تُنفذ مدفوعات حقيقية. تعريف iOS في Chromium ليس اختبار Safari على iPhone فعلي، ولم يُختبر هاتفك الفعلي.

التشغيل
1. أوقف نسخة البوت القديمة قبل بدء الجديدة لتجنب تعارض getUpdates.
2. استبدل bot.py ومجلد webapp كاملًا من هذه الحزمة، أو استخدم المجلد الكامل مع إعداداتك الحالية بجوار bot.py.
3. شغّل بالطريقة الحالية: python bot.py أو مشغل المشروع الموجود. لا تحتاج متغيرات جديدة لهذه الميزات.
4. أغلق Mini App وافتحه مجددًا لتحميل الواجهة. التغييرات التالية تظهر مع تحديث الكتالوج الدوري أو إعادة فتح المتجر.
